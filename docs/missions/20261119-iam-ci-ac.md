# IAM CI A/C: remove test bundle completion from the k6 critical path

Qualification only, on a push to `ci-iam-ac`. Compare A (native IAM and the
existing per-partition Cargo coverage) with C (instrumented IAM server/migration
and test compile jobs that start independently). k6 C waits for the successful
server job and shared runtime inputs, never the test compiler or its uploads.
Coverage C waits for the test compiler and executes the same five IAM partitions
from verified bundles. The split intentionally recompiles shared IAM dependencies
between C's two producer jobs. No outputs qualify a release or change the normal
CI, Pages, Sonar, or Telegraph gates.

Both arms use job-local cold compiler caches and the same digest-verified Cargo
download snapshot, fetched once from the locked crates.io dependencies before
compilation. Cargo is offline in consuming compiler jobs; no fallbacks to a
different cache or online fetch. No compiled outputs, Git caches, credential
files or Cargo configuration are included.

Both campaigns use the same native companion bundles and exact-run runtime base.
The common base installs the same three Ubuntu runtime packages once. The staged
Dockerfiles keep the existing app-specific runtime commands, entrypoints and ABI
proofs; per-role package installation is removed from both arms. The base is
transferred and digest-checked, not published. The E2E proof records its ID and
artifact digest. Both use the same private five-phase k6 harness. Network jitter
can still affect downloads, browser dependencies, runner apt operations and
the real test runtime. Ubuntu runner image revisions may also vary.

Measure from workflow start and report the common setup separately. For each
arm use the latest prerequisite completion for k6 eligibility, then record
actual k6 job and first case starts, coverage completion, joint completion,
occupied runner seconds excluding shared jobs, and compressed transfer bytes.
Confirm the identical Cargo archive digest in all compiling jobs, identical
runtime base provenance in both E2E reports, and all [A/B evidence
criteria](20261119-iam-ci-ab.md) with replay attributed to C. Do not reuse the
old B baseline as a controlled comparison, and do not infer a rollout decision
from missing or red evidence.
