# IAM CI C/D: reuse compiler outputs across split producer jobs

This branch-only follow-up preserves the working topology from the
[A/C experiment](20261119-iam-ci-ac.md). No production, delivery, or Telegraph
gates change. Both arms have the same sources, locked Cargo seed, prebuilt
runtime base, standard hosted runner class, native companions, five IAM coverage
partitions and five k6 scenarios. All executable consumers admit only same-run,
same-attempt outputs from their designated successful producers.

- **C control**: the server and test jobs start independently with empty Cargo
  targets and empty local sccache directories.
- **D**: the server job compiles the same binaries and uploads them, then exports
  only its content-addressed local sccache entries as a digest-checked archive.
  The test job restores that archive into an otherwise-empty local sccache and
  compiles with an empty Cargo target. Neither arm transfers `target/`.

In D, k6 does not wait for the test job, but it **does** wait for the server job's
cache export and upload; this cost counts against the variant. The tests also
start later than in C because they need the server's cache. The experiment
does not claim to validate a streaming or shared-backend architecture. Using a
same-attempt artifact keeps the experiment separate from repository-wide cache
throttling and persistent cache capacity. The cache producer and consumer run
on the same reviewed branch, toolchain and pinned version of sccache.

Measure actual sccache hits, Cargo test compilation, bytes transferred, and
export, upload, and restore time. Use completion of the required producer jobs
as k6 eligibility, not the timestamp of the server bundle upload. Compare first
k6 case, last coverage shard, joint completion and summed occupied job time.
Validate both arms against the original functional and cleanup criteria before
ranking. Do not confuse hits with a shorter pipeline or declare a wall-clock
win from one asymmetric runtime observation. No rollout is authorized here.
