# Auth Windows parent — entrypoints and private run sheet

Implemented statically, **not executed/qualified**, 2026-10-31. Governed by the
[Accepted minimal auth contract](../../../docs/contracts/k6-windows-auth-functional.md)
and [parity inventory](../../../docs/missions/20261031-k6-auth-parity.md).
Only the lead may execute on the newly admitted local-full+oauth-proof laboratory.
No historical lease/UID/source-tree pin is reused as present authority.

## Entrypoints

- `auth-inspect`: no Config or target access. Pins the existing k6/CfT tools,
  copies the two auth sources and unchanged summary.js byte-for-byte, runs k6
  version and all four closed inspections. Does not start Chrome or qualify auth.
- `auth`: requires the private Config below. Uses its run_id, which must be the
  newly deployed provider's run_id; not an unrelated GUID generated by the child.
  Performs the same inspections, then guarded certificate/OAuth phases.
- Smoke tools/browser and the old closed validate/run/selftest paths are preserved.

`lib/windows-auth.ps1` closes options, cases, 26 OAuth checks and two SAN checks.
Every summary must be current-run, expected/started/completed/iterations=1,
passes=1/fails=0 for every named check; k6/http requests=1 for SAN,0 for browser.
The latter is not a claim that Chromium made no network requests.

Duration source check: k6v2.3.0 `inspect` uses JSON serialization;
[`PerVUIterationsConfig.MaxDuration`](https://github.com/grafana/k6/blob/v2.3.0/lib/executor/per_vu_iterations.go)
is `types.NullDuration`, whose
[`MarshalJSON`](https://github.com/grafana/k6/blob/v2.3.0/lib/types/types.go)
delegates to `time.Duration.String()`. OAuth90s therefore serializes as `1m30s`.
The auth inspector accepts exactly `90s` or `1m30s`, not a wider duration range;
no generic duration parser or scenario modification was added. This is source
verification, not an executed k6 inspection.

k6v2.3.0 `inspect` uses `runtimeOptionFlagSet(false)` and does not inherit system
environment into `__ENV`. SAN module initialization therefore receives only its
closed nonsecret phase explicitly via `--env K6_AUTH_SAN_PHASE=good|bad|restored`.
No `--include-system-env-vars` or broader environment forwarding is enabled.
Source: [inspect](https://github.com/grafana/k6/blob/v2.3.0/internal/cmd/inspect.go),
[runtime env flag/merge](https://github.com/grafana/k6/blob/v2.3.0/internal/cmd/runtime_options.go).

## Fixed guarded operations and ordering

`lib/windows-auth-ops.py` is a one-shot adapter, not a server/ops backend. It
accepts only admit/snapshot/provider/bad/restore/forward. It invokes the existing CLI
`ops/deploy/local_full_target.py check` and `kubectl`, never a free shell command.
The parent starts/stops the existing CLI `oauth-forward` with retained native
child/job handles. Nothing provisions, loads images, deletes K8s resources or
adopts processes by journal/name.
The forward adapter calls the unchanged CLI main with fixed oauth-forward argv
in-process, translating Windows CTRL_BREAK to KeyboardInterrupt so its existing
context manager closes the owned child. Other ops likewise unwind their private
patch-file finally on interruption; no console-wide CTRL_C is generated.

The exclusive `<new-lease>.local-full-lock` uses the existing storage operation
lock's create-new lifetime semantics. Stale/present marker means refusal, not reset.
Live ownership is checked for IAM, provider, Envoy, Secret and ConfigMaps. Envoy's
ConfigMap data hash/key/UID/RV are bound to its actual `-c`/`--config-path` mount;
dynamic resources are refused. Provider script bytes are compared with current
source. IAM Secret references are ownership-checked, **not Secret-GET**. This is
the historical metadata/mount/config-binding proof level, not a config_dump proof.

1. Check same CA and good hostname / wrong hostname with explicit OpenSSL.
   Freeze the original good/wrong pairs in private run-owned material.
2. k6 good303 witness, then guarded Admin snapshot (positive handshake required).
3. Before possibly mutating, arm restoration. Patch only the IAM pair using a
   private **`--patch-file`**, testing Secret UID and expected original bytes.
   UID-test IAM rollout annotation; record patch/rollout ACK and replaced Pod UID.
4. k6 bad503 witness; same Envoy incarnation/epoch, fail_verify_san exactly+1,
   fail_verify_error+0.503 alone never passes.
5. In finally restore frozen original bytes, guarded rollout/ACK, k6 restored303
   and same-epoch counters/positive handshake recovery. Failure blocks cleanup.
   Before the repair PATCH, restore checks the live target/ownership, IAM
   Deployment UID and Secret UID/expected bytes, **not** IAM/provider/Envoy Pod
   readiness. The parent still requires the previous operation's proven join.
   Readiness and stable binding are checked after repair/rollout; actual patch
   and rollout ACKs are persisted before subsequent health checks. An unavailable
   pre-repair Pod UID is recorded as null, never inferred from an old journal.
6. Separate OAuth baseline. Start the existing owned provider forward, read
   provider observations with matching run_id, run the real Chromium scenario,
   read observations again, **close/join forward before Admin snapshot**.
7. Require IAM+7, ext_authz+4, provider authorize/token/profile/PKCE each0→3,
   IAM5xx+0, observed connection/TLS errors+0 and other-service requests+0.
   Missing/reset/decreased counters or changed identity/configuration are nonpositive.

The same existing Child capture loop owns all processes. Its ceiling is extended
for OAuth90s and existing rollout240s; FinishAsync lets the existing forward stay
owned during the browser case. No force-kill, new supervisor or PID recovery.

Restoration is attempted after an uncertain patch response whenever its owned
operation has ended. An unjoined possibly mutating child forbids a concurrent
repair: preserve lock/data and report cleanup failure for parent disposition.
Successful runs retire the owned run directory; failures retain only existing
bounded diagnostic names unless cleanup/restoration is blocked (then preserve all).
Raw snapshots, cert material, tokens, URLs, streams and identity journals are private.
Only closed verdicts/hashes and fixed numeric deltas are projected publicly.

## Exact future parent commands — not executed here

Before execution the lead must persist a private run sheet resolving every variable
below to an explicit observed path/value, plus cwd and new admitted target/bail.
Set K6_WINDOWS_EXE and K6_BROWSER_EXECUTABLE_PATH to the verified manifest-pinned
executables. No PATH discovery, direct k6 bypass or implicit target creation.

```powershell
$ps = Join-Path $env:WINDIR 'System32\WindowsPowerShell\v1.0\powershell.exe'
$parent = Join-Path $Checkout 'ops\tests\k6\run-windows.ps1'
Set-Location -LiteralPath $Checkout
& $ps -NoProfile -NonInteractive -File $parent -Mode auth-inspect -Output $InspectDirectory
& $ps -NoProfile -NonInteractive -File $parent -Mode auth -Output $AuthDirectory -Config $PrivateAuthConfig
```

Directories must be distinct/fresh and outside Git. The actual constructed k6 argv:

- `version`;
- `inspect <run>\scenarios\auth\oauth-browser.js`;
- `inspect --env K6_AUTH_SAN_PHASE=good <run>\scenarios\auth\envoy-san.js`;
- `inspect --env K6_AUTH_SAN_PHASE=bad <run>\scenarios\auth\envoy-san.js`;
- `inspect --env K6_AUTH_SAN_PHASE=restored <run>\scenarios\auth\envoy-san.js`;
- `run --quiet --address 127.0.0.1:0 --system-tags name,check,scenario,group
  <run>\scenarios\auth\envoy-san.js`, each guarded phase;
- the same run flags with `<run>\scenarios\auth\oauth-browser.js` once.

Each case uses its own `<case>.json` summary and the same run_id. Ops argv use
the explicit Python path: `-I -B <checkout>\ops\tests\k6\lib\windows-auth-ops.py
<closed-action> --config <private-config> --directory <owned-run> --phase <closed-phase>`.
That adapter's fixed target CLI argv are `check|kubectl --lease <new-lease>
--cluster aiforall-local-full -- <fixed-operation-args>`; patch uses the private file,
not certificate bytes in argv. Rollout is `rollout status deployment/iam -n
aiforall-local-full --timeout=240s`. Forward child argv are `-I -B
<checkout>\ops\tests\k6\lib\windows-auth-ops.py forward --config <private-config>
--directory <owned-run>`. The adapter then invokes the existing CLI main with
`oauth-forward --lease <new-lease> --cluster aiforall-local-full`.
